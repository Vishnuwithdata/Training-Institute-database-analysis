# Training Institute Database Analysis

A practical **SQL database analysis project** based on a Training Institute scenario.
This project is designed to simulate a real-world relational database and demonstrate how SQL can be used to **store, connect, query, and analyse data** to answer meaningful business questions.

## Project Overview
The **Training Institute Database Analysis** project focuses on analysing information related to students, courses, enrollments, and other training-institute operations.
The main objective is to move beyond individual SQL queries and understand how different SQL concepts work together to solve real-world data problems.
 **Learn → Query → Analyse → Generate Insights**

## Project Objectives

* Design and understand a relational database
* Establish relationships between different tables
* Work with **Primary Keys and Foreign Keys**
* Retrieve and filter data using SQL
* Combine multiple tables using different types of **JOINs**
* Use **Aggregate Functions** for analysis
* Group and filter summarized data
* Solve practical business questions
* Apply advanced SQL concepts to real-world scenarios

## Database Structure
The project contains multiple related tables representing different aspects of a training institute.

### Example entities

*  **Students**
*  **Courses**
*  **Enrollments**
*  **Instructors**
*  **Payments**
* Other supporting entities

The relationships between these tables allow meaningful analysis across different areas of the institute.

## 📊 Practical Analysis

The project focuses on answering questions such as:

Display the student name along with the course name.
Display student name, course name, and enrollment date.
Display course name along with instructor name.
Display student name, course name, and instructor name.
Display enrollment ID, student name, course name, and enrollment status.
Display student name, course name, instructor name, and course fee.
Display payment ID, student name, course name, and payment amount.
Display student name, course name, payment amount, and payment status.
B. LEFT JOIN
Display all students, including students who have not enrolled in any course.
Display all instructors, including instructors who are not teaching any course.
Display all courses, including courses in which no student has enrolled.
Display all enrollments, including enrollments for which no payment has been made.
Display all students and the courses they enrolled in, if any.
Display all courses and the students enrolled in them, if any.
C. RIGHT JOIN
Display all instructors along with their courses, including instructors who don't have a course.
Display all courses along with their enrollment details, including courses with no enrollment.
Display all enrollments along with payment details, including enrollments without payment.
D. GROUP BY + COUNT
Find the number of courses taught by each instructor.
Find the number of students enrolled in each course.
Find the number of courses enrolled by each student.
Find the number of students from each city.
Find the number of enrollments for each enrollment status.
Find the number of payments for each payment status.
Find the number of students enrolled under each instructor.
E. GROUP BY + SUM
Find the total course fees for each instructor's courses.
Find the total amount paid by each student.
Find the total payment received for each course.
Find the total payment collected for each payment status.
Find the total revenue generated by each instructor.
These questions help demonstrate how SQL can be used to transform raw database records into useful information.
